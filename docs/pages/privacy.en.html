Privacy Policy

Last updated: September 29, 2026

Overview

AREITU does not run its own server. Your data is never sent to a server operated by the developer, and the developer has no access to it. Your visit-log data (areitu.db, a SQLite file) is stored on your device's local disk. If you sign in with your Google account, this file is also stored in and synced with the "appDataFolder" of your own Google Drive. This folder is not shown in the normal Google Drive UI and is not accessible to anything other than AREITU's OAuth client.

AREITU does not encrypt the database itself. Neither the local areitu.db nor the copy on Drive is encrypted by AREITU (Google's own encryption at rest applies to the copy on Drive).

Data handled

  • Capture time and location (latitude/longitude) read from photos in the folders you specify. The photo files themselves are not sent anywhere.
  • Visits derived from them (times, coordinates, inferred place names).
  • Only if you enable calendar import: your Google Calendar events (title and time range).

Google OAuth scopes requested

  • https://www.googleapis.com/auth/drive.appdata: always requested at sign-in. Used only to upload and download areitu.db to and from the appDataFolder of your own Google Drive. When a sync conflict occurs, a backup copy (areitu-conflict-<timestamp>.db) is also created in the same folder.
  • https://www.googleapis.com/auth/calendar.readonly: requested only if you enable calendar import in Settings. Used to read events as hints for inferring the place name of visits in the same time range. AREITU never modifies your calendar.

When data leaves your device

The following is everything AREITU sends over the network. Each destination also receives your IP address as part of the connection.

  • Reverse geocoding (enabled by default): to infer a place name, the latitude/longitude of a visit is sent to OpenStreetMap's Nominatim (nominatim.openstreetmap.org). If you enable Google Places in Settings and enter an API key, the coordinates are sent to the Google Places API (places.googleapis.com). Nothing is sent for coordinates already registered in the app's local dictionary.
  • LLM place-name inference (disabled by default): runs only if you select an LLM in Settings. When reverse geocoding yields no facility name, or the name disagrees with a calendar event, the following is sent as a prompt: the visit's start and end times, latitude/longitude, the reverse-geocoding address and facility name, and the titles of calendar events in the same time range. The destination depends on your choice:
    • Ollama: the URL you configure (default is the same machine, http://localhost:11434). If you point it at another host, the prompt goes to that host.
    • OpenAI: api.openai.com (using your API key)
    • Gemini: generativelanguage.googleapis.com (using your API key)
  • Google sign-in and sync: if you sign in, AREITU communicates with accounts.google.com, oauth2.googleapis.com and www.googleapis.com (Drive, and Calendar if calendar import is enabled). While signed in, areitu.db is synced automatically at the polling interval you set.
  • Update check: the app fetches update information from GitHub (github.com/ikeikeikeda66/AREITU/releases).

AREITU sends nothing else. It sends no data for advertising or analytics.

Google user data (Limited Use)

AREITU's use and transfer to any other app of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

  • Drive data is used only to sync your own database. Calendar data is used only to infer place names for visits.
  • Google user data is not transferred to the developer or to third parties. The one exception is that, if you enable an LLM as described above, calendar event titles are sent to the LLM destination you chose.
  • Google user data is not used for advertising.
  • The developer does not read Google user data (the developer has no access to it).

Where data is stored

  • Visit database: areitu.db in the OS application-data directory (identifier com.areitu.desktop)
  • Sync state: files such as google-calendar-state.json in the same directory
  • Settings: config.json in the OS application-config directory (contains no API keys)
  • OpenAI / Gemini / Google Places API keys and the Google refresh token: only in the OS keychain (keyring)
  • Copy made by Drive sync: the appDataFolder of your own Google account

How to delete your data

  1. Signing out in AREITU's Settings deletes the Google refresh token stored in your device's keychain. It does not revoke access on Google's side or delete data on Drive.
  2. Removing AREITU's access on your Google Account third-party access page stops AREITU from accessing your Google data from then on.
  3. To delete the copy on Drive, open Google Drive, go to Settings, then Manage apps, select AREITU and choose "Delete hidden app data" (if AREITU is no longer listed, do this before removing access above).
  4. To delete data on your device, uninstall AREITU and delete the com.areitu.desktop folders under the OS application-data and config directories (areitu.db, config.json and related files). Remove stored API keys with your OS keychain tool.
