# AREITU ロードマップ

**Spec:** AREITU 基本構想書 https://docs.google.com/document/d/1OPiPQLFQdxd31uZOQzWQORTyrvs1roQS_XW_ykYPj6E/edit （「9. 実装ロードマップ」）

各 Phase は GitHub の Milestone に対応する。Phase 1 は詳細プランを作成済み。Phase 2 以降は、着手時に同じ形式（TDD のステップ単位）の詳細プランを `docs/superpowers/plans/` に追加する。Phase 1 の実装結果（API の形、推論精度）が Phase 2 以降の設計に影響するため、今の段階では issue 粒度にとどめる。

## Phase 1: コアエンジン & DB設計

詳細プラン: [2026-09-26-phase1-core-engine.md](2026-09-26-phase1-core-engine.md)

| # | タスク | 構想書の対応項目 |

| 5 | 訪問候補のクラスタリングとカレンダー突合 | 同上 |

## Phase 2: デスクトップアプリ構築（Tauri + React）

詳細プラン:
- 2A デスクトップアプリ（#11–#15）: [2026-09-27-phase2a-desktop-app.md](2026-09-27-phase2a-desktop-app.md)
- 2B Google OAuth と Drive 同期（#17, #16）: [2026-09-27-phase2b-google-sync.md](2026-09-27-phase2b-google-sync.md)。最終タスクは 2A 完了後に実行する

Drive 同期に Google ログインが必要なため、OAuth 2.0 PKCE（#17）を Phase 3 から Phase 2 に移した（2026-09-27 決定）。

| タスク | 内容 |
|---|---|
| Tauri + React (Vite) + Tailwind の雛形 | `apps/desktop` に Tauri 2 アプリを作り、`areitu-core` を依存に追加。Tauri command で `list_places` / `visits_of` / `rename_place` を公開 |
| 検索・一覧画面 | インクリメンタル検索、訪問回数順／直近訪問日順の切り替え |
| 店舗詳細カードと手動修正 UI | 店舗名・通算訪問回数・訪問日時一覧、名前のインライン編集（`rename_place` 経由で辞書に記録） |
| トレイ常駐・自動起動・定期ポーリング | システムトレイ、OS 起動時の自動実行、監視フォルダの定期走査と `build_visits` の定期実行 |
| LLM・推論設定画面 | Ollama／クラウド API（OpenAI / Gemini）の選択とキー入力、Google Places API キー（任意）。キーは OS のキーチェーンに保存 |
| デスクトップ向け OAuth 2.0 PKCE | ループバックリダイレクトで Google ログイン。この段階の要求スコープは `drive.appdata` のみ（`calendar.readonly` は Phase 3 で追加） |
| Google Drive (appDataFolder) バックアップ/同期 | `areitu.db` を `drive.appdata` スコープでアップロード・ダウンロード。両方変更時はローカルを優先してアップロードし、リモート側を `areitu-conflict-<時刻>.db` として残す |

**完了条件:** Mac と Windows でアプリが起動し、常駐したまま新しい写真が自動で訪問に反映され、画面から検索・修正ができる。

## Phase 3: 一般配布・オンボーディング対応

- 3A アプリ機能（#18, #19, #20 と設定画面の Google アカウント欄）: [2026-09-28-phase3a-app-features.md](2026-09-28-phase3a-app-features.md)
- 3B 配布（#21, #22 と CSP 設定）: [2026-09-28-phase3b-distribution.md](2026-09-28-phase3b-distribution.md)

2026-09-28 決定: コード署名・公証は当面行わない（未署名で配布し、開き方を README に書く）。プライバシーポリシーは GitHub Pages で公開する。

| タスク | 内容 |
|---|---|
| Google Calendar API からの自動取得 | `calendar.readonly` スコープを追加で要求し、Phase 1 の `parse_events` に `events.list` のレスポンスを渡す。差分取得（syncToken） |
| 初回セットアップ画面 | 監視フォルダ選択、Google 認証、LLM 設定。設定画面に Google アカウント欄（サインイン・サインアウト・Drive 同期）を追加 |

| OAuth 審査対応 | プライバシーポリシー（GitHub Pages）、同意画面、審査申請 |

**完了条件:** 一般ユーザーが GitHub Releases からインストールし、「Googleでログイン」とフォルダ選択だけでセットアップを終えられる。
